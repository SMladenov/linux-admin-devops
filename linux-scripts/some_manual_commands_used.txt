To separate a .pfx file into a private key (.key) and certificate (.pem)
Extract the Private Key:
openssl pkcs12 -in yourfile.pfx -nocerts -out extracted.key -nodes #(-nodes: Prevents encryption of the private key.)
 Extract the Certificate:
 openssl pkcs12 -in yourfile.pfx -clcerts -nokeys -out extracted.pem
 Optional: Extract CA Certificates (If Needed):
 openssl pkcs12 -in yourfile.pfx -cacerts -nokeys -out ca-certificates.pem
 Verify the Outputs:
 Test the private key:
 openssl rsa -in yourname.key -check
 View certificate details:
 openssl x509 -in cert.pem -text -noout
 Update Certificate Store:
 sudo update-ca-certificates

#%Cpu(s):  0.0 us,  0.2 sy,  0.0 ni, 99.8 id,  0.0 wa,  0.0 hi,  0.0 si,  0.0 st
us -> User CPU -> Time spent running applications (nginx, java, python) -> High us = app-heavy workload
sy -> System CPU -> Time spent in kernel (syscalls, disk/network handling) -> High sy = kernel doing work (I/O, drivers)
id -> Idle -> CPU usage ≈ 100 - id
wa -> I/O wait (VERY IMPORTANT) -> CPU is idle BUT waiting for disk -> High wa = storage problem
st -> Steal time (VERY IMPORTANT for VMs) -> CPU time taken by hypervisor -> High st means:
					  -> your VM is not getting CPU
					  -> host machine is overloaded


#Inodes
An inode is a data structure that stores metadata about a file
- file size, permissions, owner (UID/GID), timestamps (created, modified, accessed), pointers to disk blocks (where data is stored)

Filesystem has a limited number of inodes
- You can run out of disk space OR inodes

Why inodes get exhausted:
- Many small files -> logs, cache files, temp files, mail queues

##6. Explanation of different /boot components

1. vmlinuz — The Linux Kernel
This is the actual Linux kernel executable
GRUB loads this file into memory -> GRUB -> vmlinuz -> Kernel starts executing
#You can think of it as: Linux operating system core

2. initrd.img
After the kernel starts -> GRUB -> Kernel -> Initramfs
#Contains: kernel modules, drivers, scripts
#needed before the real root filesystem is available

3. config — Kernel Build Configuration
#This tells you how the kernel was compiled
#Open it: less /boot/config-6.1.0-44-amd64

#Real Boot Sequence
BIOS/UEFI -> GRUB -> vmlinuz -> initrd.img -> mount root filesystem -> systemd -> services -> login
